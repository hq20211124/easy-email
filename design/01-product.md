## 1. 一句话定位与产品原则

> **Easy Email 是一个"零配置、本地优先、够快、不作恶"的 Windows 桌面邮件客户端。**
> 填一个邮箱地址就能用；邮件在本地，断网也能读、能搜、能写；不需要注册任何账号，
> 不收集你的通讯录，不塞广告。

五条产品原则（冲突时按此优先级裁决）：

1. **可靠 > 好看 > 功能多。** 一封信丢了，界面再美也没用。
2. **默认安全**，但安全不能变成折磨：默认拦截远程内容、默认不信任附件，
   同时把"为什么"和"怎么放行"讲清楚，一键可解。
3. **本地优先**：核心体验（读、搜、写、整理）不依赖任何我们运营的服务器。
4. **快是功能**：冷启动、滚动、搜索的毫秒数写进预算，不达标就算没做完。
5. **用户的邮箱是用户的**：可导出、可删除、可带走；不做锁定。

## 2. 目标用户与场景

| 代号 | 用户 | 特征 | 他们最在意 | 我们凭什么赢 |
|---|---|---|---|---|
| **U1 大陆办公用户** | 用 QQ/163/企业微信邮箱收发工作邮件，可能还挂着 Gmail | 邮箱多、附件多、网络时好时坏、怕丢信 | 国内邮箱能不能一次配好、中文搜索准不准、断网能不能用 | 21+ 家内置配置 + 中文分词搜索 + 离线可用（现状优势，继续加固） |
| **U2 多账号重度用户** | 个人 Gmail + 公司 M365 + 学校邮箱 | 一天几百封、会话长、要找三个月前的附件 | 会话串、搜索、快捷键、批量操作、稳定不掉线 | 会话串 + 全文搜索（含附件名/正文）+ 命令面板 + 虚拟列表 |
| **U3 隐私敏感 / 技术用户** | 反感遥测、用 PGP、习惯 Thunderbird | 控制权、可导出、无广告、无账号 | 本地存储、无遥测、PGP、可脚本化/可迁移 | 本地优先红线 + PGP/S-MIME + 一键导出 + 无遥测 |
| **U4 从旧客户端迁移过来的人** | 现在用 Foxmail / 网易邮箱大师 / Outlook 经典版 | 存量邮件多、配置复杂、怕重新配一遍 | 迁移省事、界面熟悉、别丢邮件 | 一键迁移向导（账号 + 服务器全量重同步 + 本地导入 + 联系人） |

**典型首日旅程（必须顺到不需要说明书）**：
下载 → 双击安装（无 cmd 窗口、无 WebView2 阻断）→ 首次运行向导 → 输入邮箱 →
自动识别服务商 → OAuth 一键授权或授权码引导 → 立即看到最近邮件（先头后体）→
后台默默把窗口内的邮件拉全、建立索引 → 首次搜索在 1 秒内出结果。

## 3. "凭什么换过来"——七条可验证的差异点

| # | 差异点 | 竞品现状（粗粒度，2026） | 我们的做法 | 可验证指标 |

| D3 | **搜索准且快（中文）** | 多数国产客户端搜中文子串会漏；Outlook 依赖 Windows Search | 自建索引（正文 + 附件名 + 可选附件文本），CJK 分词正确 | 2 字中文词命中率 100%（夹具）；10 万封 < 100 ms |

| D5 | **安全默认 + 讲清楚** | 多数客户端默认加载远程图片（追踪像素）；钓鱼提示参差 | 默认拦截 + 跟踪器统计 + 外发/相似域名提示 + 链接真实域名悬停 | 默认不产生任何外部请求（可抓包验证）；每封邮件显示跟踪器数量 |
| D6 | **不作恶** | 部分国产客户端带推广、资讯流、强制登录、上传通讯录 | 无广告、无资讯、无账号体系、无遥测（默认） | 安装包内无第三方统计 SDK；出站连接白名单可审计 |
| D7 | **数据可带走** | 生态锁定（标签/规则/本地邮件难导出） | 一键导出 mbox/eml/设置/规则/联系人；缓存可删可重建 | 导出后可被 Thunderbird 直接导入（人工验收） |

> 竞品结论只用于排优先级，不作为对外宣传口径；实装前若要写进 README，需重新核实（记入 §12）。

## 6. 明确不做（以及需要你解除原决定的三项）

已否决、本设计**默认仍不做**（要改请明确说，我按新决定重写对应文档）：

| 不做的事 | 理由 | 如果不做的代价 |
|---|---|---|
| 自建邮件服务器 | 与"本地优先、不运营服务器"冲突 | 无（用户本来就不需要） |
| 服务端 Sieve 界面 | 面向极小众、协议支持参差 | 少数用户需去网页端设规则（本地规则引擎 RULE-01 覆盖大部分需求） |
| 完整所见即所得 HTML 邮件设计器（newsletter 排版） | 成本极高、与我们"轻量可靠"的定位冲突 | 需要发营销邮件的用户不适合本产品 |

**需要你确认是否解除原决定的三项**（本次指示是"能做的都要做进来"，所以我列出来并给了成本）：

| 项 | 原决定 | 若要做 | 成本/风险 |
|---|---|---|---|
| POP3（PROTO-06） | "不把 POP3 当主线"（可做兜底） | 做，但明确标注"仅兜底、不推荐" | M（周级）；语义坑多（UIDL、删信、多端不同步） |
| 富文本/HTML 写信（MAIL-01） | 否决的是"完整 WYSIWYG HTML 设计器"，不是富文本 | 做**受限富文本**（粗体/斜体/列表/链接/引用/签名，生成干净 HTML） | L（月级，主要在"生成干净可读的 HTML"与"防注入"） |
| 日历（CAL-01…05） | 未讨论过 | 做：先邀请只读（CAL-02），再做完整日历（CAL-01/03） | L+（月级到季级），且是另一个产品面的维护成本 |

| **P9** | **默认同步窗口** | ① 全部 ② 最近 2 年 ③ 最近 1 年 | **②**（可在 ACC-14 改）；大邮箱首日体验与磁盘占用的平衡点 | 04，SYN-01 |
| **P10** | **更新通道** | ① 只有稳定版 ② 稳定 + 预览 | **②**（预览通道用于自己吃狗粮） | 17，REL-10 |
| **P11** | **界面语言** | ① 中文优先，英文 M2 ② 只要中文 | **①**（i18n 的地基要在 M1 就打，后补会痛） | 12，UI-08 |

| **P13** | **PST/OST 导入** | ① 不做（推荐） ② 捆绑 `pffexport` sidecar | **①不做**：没有纯 Rust 实现（自研 L+ 数月）；唯一可行路线要捆绑一个**许可证在仓库内自相矛盾（GPL-3 / LGPL-3）**的 C 二进制，且 Classic Outlook 2026-04 已进 opt-out、**New Outlook 没有 MAPI** ⇒ 这条路的寿命只剩几年。真正的替代路径是"用 IMAP/Graph 直接连同一个邮箱"（MIG-05） | 06 |
| **P14** | **导入其它客户端保存的密码**（Thunderbird `key4.db`+`logins.json`） | ① 不做（推荐） ② 做 | **①不做**：技术上 1-2 周可解（PBKDF2+AES-256-CBC），但"解密别的客户端的密码库"与凭据窃取工具无法区分，会被 AV/EDR 与商店审核盯上，还把自己变成高价值目标。**改为让用户重登一次（60 秒）** | 06 |
| **P15** | 发布渠道优先级 | 官网 zip + GitHub Releases + winget → 后加微软商店 | 同上 | 17 |
| **P16** | 更新清单托管地 | 默认 GitHub Releases（免备案）；预留镜像设置项 | 同上 | 17 |

## 8. 成功指标（可测，验收时逐条量）

**体验**：冷启动 ≤ 1.5 s｜切文件夹 ≤ 200 ms｜滚动 60 fps @ 10 万封｜本地搜索 ≤ 100 ms｜
常驻内存 ≤ 300 MB｜安装包 ≤ 30 MB｜首次配置 ≤ 3 次点击｜首屏邮件 ≤ 3 s（已缓存时 ≤ 500 ms）。

**可靠性**：草稿零丢失（崩溃/断电夹具）｜离线发送 100% 入队并在联网后 100% 送达｜
同步零丢信（gap-free 夹具 + 真实大文件夹验证）｜崩溃率 < 0.1%/会话｜
任意失败都有可行动中文提示（无裸库错误）。

**信任**：**打开/阅读邮件时零外部请求**（抓包验证）；全部出站请求 ⊆ 14 §11 的端点清单（**更新检查默认开启**，会带版本与架构去清单地址 —— 如实披露，不写成"绝对零请求"）｜缓存库与日志中零明文凭据（脚本扫描）｜
安装包内无第三方统计 SDK｜数据可完整导出并被 Thunderbird 打开。

**留存（主观但可量化地观察）**：日常使用 7 天后仍设为默认邮件客户端（DIST：mailto 注册率）｜
不用回网页端做日常操作（即本地规则/搜索/整理够用）。

## 9.5 逆向反驳（红队，产品层面）

**反驳 1：193 项功能对单人维护者等于"永远做不完"，最后每一样都半成品 —— 这比只做 20 项更糟。**
- 证据：M1a+M1b 已经是 5-9 人月，M2/M3 再加 9-17 人月（`19` §2）。
- 缓解：①**里程碑切分**（M1a 就能发布并推荐给朋友用）；②每个块有 DoD（`19` §5）与"可停可续"纪律；
  ③**"不做清单"也是产品的一部分**（`01` §6），明确写出"哪些我们故意不做"，避免半成品堆积。
- 让步：如果时间预算更紧，**优先砍 M2/M3 而不是稀释 M1**（M1 是"能不能换过来"的门槛）。

**反驳 2："不要设限制，能做的都要做进来"会让产品失去焦点**（邮箱客户端做成"什么都有但什么都不精"）。
- 证据：国产客户端常见这个病（资讯流、广告、云盘、笔记全塞进来）。
- 缓解：①**核心仍是邮件**：读、写、找、整理四件事的质量优先；
  ②扩展项（PGP/日历/协议）**排在 M3**，且都要回答"它让邮件体验更好吗"；
  ③红线 6（不要我们运营的服务器）天然挡掉了大量"平台化"诱惑。
- 让步：如果用户明确要"办公套件"（邮件+日历+任务+通讯录一体），那是一份**新的产品定义**，
  需要重写 `01` 而不是在 M3 里塞进去。

**反驳 3：竞品对标表（§4）是"粗粒度、可能过期"的，用它排优先级会不会排错？**
- 证据：表里 ✅/⚠️/❌ 的很多格子来自 2026 年的观察，随时会变。
- 缓解：①只用于**排优先级**，不作为宣传口径（已写明）；②实装前若要写进 README，必须重新核实；
  ③真正决定优先级的是"用户可感知差异点"（§3）与"可靠性缺口"（§Rabbit 的风险登记册），
  而不是竞品有没有这个功能。
- 让步：把这张表当作"半年一更新的快照"，而不是长期事实。

**反驳 4：§3 的七条差异点里，好几条竞品也在做**（本地优先、跟踪防护、无广告都成了卖点）。
- 证据：确实。可复制性意味着"差异点"会随时间贬值。
- 缓解：把难被复制的组合当成真正的护城河：**中文邮箱深度（21 家内置 + 中文分词 + 中文文案）**
  × **诚实的配额/同步行为（不骗用户"全部同步完成"）** × **数据可带走（导出能被 Thunderbird 读）**
  × **快与小**。单一功能可以被抄，组合与纪律不容易。
- 让步：接受"我们不靠某个功能赢"，而是靠**整体可靠与克制**。

**反驳 5：U1（大陆办公）与 U3（隐私技术用户）的需求互相冲突**（一键配好 vs PGP/本地加密/无遥测）。
- 缓解：**分层**而不是折中：默认简单（一键 OAuth/授权码、默认安全、零外部请求），
  进阶可深（PGP、BYO client_id、同步窗口、规则引擎、导出）。UI 上把进阶能力放进"高级"，
  不占普通用户的视野（`12` §7）。
- 让步：不为极端隐私需求做"全程 Tor/无痕模式"这类功能（与邮件协议的现实冲突）。

**反驳 6：§8 的成功指标有主观项（"愿意设为默认邮件程序"），不可直接测。**
- 缓解：换成可测代理指标：①mailto/.eml 注册率（能读到系统状态）；②7 日留存（本地打点，不上传）；
  ③离线操作次数（证明 D2 被真实使用）；④搜索零结果率（衡量索引覆盖）；
  ⑤发件箱一次成功率（衡量可靠性）。全部只存在本地，用户可在设置里看（也符合红线）。
- 让步：不引入任何"上传指标"的机制。

**反驳 7：功能全集没有"成本合计"，用户看到清单无法判断该砍什么。**
- 证据：这正是 §4/§9 缺的东西，已由 `19` §2 补上（每个里程碑的人月区间）。
- 缓解：①`19` 给出规模与依赖；②本文 §7 的 12 项决策里，每一项都写"影响面"，便于按影响砍；
  ③**砍范围必须由用户明确决定**（我给出建议，但不擅自删功能 ID）。
- 让步：如果总规模超出预算，建议顺序是：砍 M3 → 砍 M2 的一半 → 冻结 M1b 的性能打磨（但 M1a 不砍）。
